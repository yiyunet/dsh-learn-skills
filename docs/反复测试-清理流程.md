# 反复测试：删除流程（定版 · 六步 + 复核）

> 适用：本插件（AI学习）反复建预设／建工作区做测试之后，把痕迹清干净。
> 判据一律**放在文件内容里**（生成标记／登记路径是否存在），不靠目录名猜。
> 配套工具：`scripts/clean-test-state.mjs`（默认干跑；`--scan` 只读体检；`--only` 只删指定预设）。
>
> **★2.1.0 起两处变化（下文的步骤照旧，但要知道）**：
> ① **预设 bundle 落点搬进工作区**：`<工作区>/.dsh/preset-bundles/<id>/`。
>    工具不给 `--preset-root` 时**默认就扫这里**；旧版宿主级落点
>    `<dshHome>/preset-bundles/` 不再被默认扫描（那里住着部署方自己的组合包，
>    如 `dsh-migrated-presets`，**不属于本插件，不要当残留删**）。
> ② **安装不再由插件代做**：装了 bundle 才进名册（`preset-<id>` 行），
>    而**删掉工作区文件夹会连带废掉里面的预设** —— 于是"删工作区"这一步
>    多了一条前置：**先从 profile 摘掉该 bundle**，否则那些会话会被拒绝恢复。

## 〇、先纠三处（原版流程里会误伤/会看漏的地方）

| # | 原版写法 | 问题 | 改成 |
|---|---|---|---|
| 1 | 第 4 步「或跑一次 `… --yes`，它顺带清工作区状态与插件生成的预设」 | **不加筛选的 `--yes` 会删掉该预设根下「所有」本插件生成的预设**，而第 1 步只想删一个 ⇒ 前后矛盾、且会误删 | 第 4 步改为二选一：**只清工作区状态** `--state-only`，或**只删那一个预设** `--only <id>`；**别用裸 `--yes`** |
| 2 | 全流程没有"先看有什么 / 后看清干净没" | 无法判断"哪些已删、哪些是残留" | 加 **第 0 步体检**（`--scan`，只读）与 **第 6 步复核**（再 `--scan`） |
| 3 | 第 3 步删完工作区文件夹后，第 4 步还要"清工作区状态" | **冗余**：工作区状态就在该文件夹里（`<工作区>/.dsh/learn-skills/`），删了文件夹它已经没了 | 第 4 步只剩"删诊断日志"（或整步跳过） |

## 一、定版六步

### 第 0 步 · 体检（只读，永远安全）

```powershell
cd <本仓库目录>
node scripts/clean-test-state.mjs --scan --workspace <工作区>
```

**记下三样**：①哪些预设是"插件生成"（带生成标记）、有没有"★疑似测试残留"；
②工作区登记里有没有"✗ 路径已不存在"的**孤儿登记**；③工作区状态里有没有**死引用**。

### 第 1 步 · 撤掉那一个预设（一次只删一个）

> **★ 订正（原文写的是「设置 → Agent 预设 → 删除」——该入口在新版不存在）**：
> DSH **0.1.7-alpha.1 起预设改为声明式**，设置页对预设**只能查看 / 选择 / 设为默认**
> （只读清单＋只读的「查看配置」YAML 查看器），**没有任何删除动作**。能删的只有
> **它所在的 bundle**。完整四步法与三种形态见 [`删除预设.md`](删除预设.md)。

```powershell
# ① 先摘依赖（顺序在前）：包名＝@local/dsh-learn-preset-<预设id>
dsh plugin --profile web remove @local/dsh-learn-preset-<预设id>

# ② 再删工作区里的 bundle 目录（本插件的工具只删目录，不会替你摘依赖）
node scripts/clean-test-state.mjs --only <预设id> --workspace <工作区> --yes

# ③ 最后清本插件的占用记录（否则同名重建会拿到 -2 后缀）
#   <工作区>/.dsh/learn-skills/known.json → presetNames / presetIds 里删掉那两条
```

> ⚠️ **2.1.0 起多一条前置**：本插件生成的预设是**工作区内的 bundle**，删工作区文件夹会
> 连带废掉它。要保留工作区、只撤预设时，**必须先把它从 profile 摘掉**（否则重启后那些
> 会话会被拒绝恢复）；**反过来"只删目录不摘依赖"会让宿主启动时提示跳过该 bundle**。

- **判据**：`plugin_manager` 的 `list_plugins` 里 `preset-<预设id>` 行消失 ⇒ 第 6 步复核时
  它的 id **不再出现在清单里**。
- 要删多个就重复这一步。**不建议**用裸 `--yes` 一次全清（除非你确实要清空所有测试预设）。

### 第 2 步 · GUI 删工作区登记

`工作区 → ⋯ → 删除工作区`。宿主语义（源码原文）：*"Delete one Workspace registration
**without deleting its directory or Sessions**."* ⇒ **只清登记**。

### 第 3 步 · 删掉该工作区文件夹

只删**测试用的那个**（例：`<工作区>\`）。
⚠️ 顺序必须在第 2 步**之后**（先删目录会让 GUI 删除因路径不存在而失败）；
⚠️ 别对有真实内容的工作区（你日常在用的那个）做这一步。

### 第 4 步 · 删诊断日志（可选）

```powershell
Remove-Item "$env:USERPROFILE\.dsh\learn-skills-boot.log" -ErrorAction SilentlyContinue
```

单文件，下次启动会重建。**若你想"清插件记忆但保留工作区"**（不删文件夹），才需要这条：

```powershell
node scripts/clean-test-state.mjs --workspace <工作区> --state-only --yes
```

### 第 5 步 · 重启宿主 web

预设名册是"**一进程只挂载一次**"；不重启的话，被删的预设可能仍出现在列表里。

### 第 6 步 · 复核（只读）

```powershell
node scripts/clean-test-state.mjs --scan --workspace <工作区 或 已删则省略>
```

**"干净"的判据**：①预设清单里**没有**"★疑似测试残留"；②登记里**孤儿登记 0 条**；
③工作区状态栏显示"不存在"（文件夹已删）或"死引用 0 个"。三者齐 ⇒ 收工。

## 二、仍会看到的（**不是插件残留**，别去找本插件）

| 位置 | 属谁 | 说明 |
|---|---|---|
| `~/.dsh/storages/session_projcache*` | 宿主 | 会话索引缓存（标题/首问）。**不要整目录删** —— 它含你所有会话 |
| 会话历史本体 | 宿主 | 第 2 步明确"**不删 Sessions**"；当前 GUI **只能归档、不能删除对话**（我核过 `session-controller` 的 15 个 remote，无 delete） |
| `~/.dsh/logs/startup-*.log` | 宿主 | 启动日志，无害 |
| `~/.dsh/integrations/dsh-dingtalk/workspaces.json` | 另一插件 | 只在你用过钉钉取数时才有 |
| `deepseek-harness` 检出目录 | — | **本就零残留**：插件所有写入都是绝对路径（`<工作区>/…`、`homedir()/.dsh/…`） |

## 三、一句话版（记住这条顺序就不会错）

> **先体检 → 撤掉那一个预设（摘依赖 → 删目录 → 清占用）→ GUI 删工作区登记 →
> 删工作区文件夹 →（可选）删 boot log → 重启宿主 → 再体检复核。**

三条铁律：**① 任何删除前先跑不加 `--yes` 的干跑或 `--scan`；② 删工作区永远"先 GUI 后目录"；
③ 裸 `--yes` = 清空所有本插件生成的预设，只删一个请用 `--only`（且先摘依赖）。**

> 只删**一个预设**、不动工作区时，走 [`删除预设.md`](删除预设.md) 的四步法；
> 本文只管"反复测试后把整片测试痕迹清掉"。
