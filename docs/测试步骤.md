## §0 失败对照表（先看这个）

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| `npm run static` 报"引用了不存在的文件"或"导入了未导出的符号" | 我改代码时留下的真错 | **把报错原文发我**，这是一条真缺陷，不要自己改断言 |
| `npm run build` 报 `Cannot find package 'esbuild'` | 没跑 `npm install` | 先 `npm install` |
| `npm run build` 报"连续 N 次遇到瞬时文件锁（EPERM/EBUSY）" | Windows：杀软/索引器/宿主进程持有 `lib/` 句柄 | 关掉正在加载该目录的 DSH，或把目录加进杀软排除项，重跑 |
| `npm run verify` 报"发现可能的私有信息泄漏" | 源码/文档里混进了本机绝对路径或令牌形态 | **不要改断言**；把命中行发我，它指向真正的泄漏面 |
| `npm run verify` 报"files 白名单里的 X 在磁盘上不存在" | 白名单与磁盘不符 | 发我 |
| `dsh plugin add` 后菜单**没出现** | ① 没重启 Host ② `lib/client.js` 不存在 ③ 客户端产物装配位置错 | 依次查：重启了吗 → `dir lib` 有 `client.js` 吗 → 开 DevTools Console 看有没有报错 |
| 菜单出现了但点了没反应 | RPC 端点没注册（宿主缺 `connection.fetch`） | 看宿主日志有没有 `宿主未提供 connection.fetch.register` 这行 |
| `/learn` 不在斜杠菜单里 | 宿主缺 `ctx.commands`（插件会停在 inactive） | `dsh --profile web --dump-config` 看 `commands` 行在不在 |
| 六题问了但输不进字 | 不是本插件的问题（问题由宿主的问答合成器渲染） | 换个干净会话再试；仍不行则记现象发我 |
| 提示"当前会话没有绑定工作区" | 会话没绑工作区 | 在输入区选/新建一个工作区 |
| 点「初始预设」**立刻**报"无法读取宿主预设名册（agentPresets）" | 宿主没把 `ctx.agentPresets` 解析给插件（2.1.0 起这是**刻意的拒绝路径**：拿不到名册就无法保证不生成重复 `config.id`） | **把提示原文发我**（这同时是我方风险 N1 的探针）；在此期间其余三个入口不受影响，手工加预设照旧 |
| 点「确认创建」后提示"尚未安装"、要求你跑一行命令 | **正常现象**（2.1.0 起刻意不代装：装 bundle＝在 Host 执行新代码，官方入口强制审批） | 照提示跑 `dsh plugin --profile web add link:<该目录>`，或在「创造模式」里用 `plugin_manager`（会弹审批卡） |
| 装完重启，新会话里选不到该预设 | ① 没重启宿主 ② 装的是别的 profile ③ 该声明激活失败（roster 里带诊断） | ① 重启 ② 检查 `--profile web` ③ 用 `plugin_manager` 的 `list_plugins` 看 `preset-<id>` 行的状态（`broken` 有值即为激活失败） |

## §1 Phase 1：构建与测试（不需要 DSH）

> ⚠️ **Windows PowerShell 5.1 不支持 `&&`**（那是 PowerShell 7+ 的语法）：`npm test && npm run verify`
> 会报「标记"&&"不是此版本中的有效语句分隔符」。**三条照用**：
> ① 直接跑 `npm run check`（它就是 static→build→test→verify 的串行链，最省事）；
> ② 分两条跑 `npm test` 然后 `npm run verify`；
> ③ 非要在 PS 5.1 里连跑，用分号 `npm test; npm run verify`（**注意**：分号**不短路** —— 前一条失败也会继续跑）。

### 1.1 进目录

> 下面用 `<插件目录>` 代指本仓库实际位置（例：`<工作区>/dsh-learn-skills`）。
> **把 `<插件目录>` 替换成真实路径即可**；本文档刻意不写死本机绝对路径。

```powershell
cd "<插件目录>"
```

### 1.2 静态一致性体检（**零依赖，先跑这个**）

```powershell
npm run static
```

**期望输出**：

```

✓ 通过（相对 import 齐全、具名符号存在、语法可解析、客户端模块白名单、宿主依赖面）
⚠️ 这只证明静态一致性，**不证明行为** —— 必须另外跑 npm test / npm run verify。
```

> 这一步不需要 `npm install`。它的价值：把"改名漏改""import 了不存在的文件"这类**免执行就能抓**的错先清掉。

### 1.3 装依赖 + 构建


**期望输出**（节选）：


① 客户端产物**顶层能执行完**（否则说明它被放在了 wrapper factory 外面，会把整个 `/plugins` 拼接包搞死）；
② 它**真的注册了** `@yiyunet/dsh-learn-skills`；
③ 它的 factory **真的产出了 `apply()`**。

### 1.4 跑测试

```powershell

```


## §2 Phase 2：装载（装进 profile 并重启）

### 2.1 确认现在装的是什么

```powershell
dsh plugin --profile web why @yiyunet/dsh-learn-skills
```

**期望输出**：报错或提示"未找到"——**这是正常的**，说明还没装。

### 2.2 装本地目录（link）

```powershell
dsh plugin --profile web add "link:<插件目录>"
```

**期望输出**：pnpm 输出 `+ @yiyunet/dsh-learn-skills 2.1.0`，并且 **`dsh plugin` 会自动把它并入 profile 的 bundles 列表**。

> ⚠️ **必须用 `dsh plugin add` 装，不要手工往 profile 的 `package.json` 里加一行**。
> 原因（源码依据）：`dsh plugin` 走 `runPluginCommand` → `runProfilePnpm`，退出码 0 时才执行
> `reconcile()` 把新依赖并入 `dsh.profile.bundles`（`plugin-manager/src/operations.ts:73-97`）。
> 手工编辑 `package.json` 会跳过这一步 —— 包在盘上但**不会被装载**。

### 2.3 回读确认（不凭终端印象）

```powershell
dsh plugin --profile web why @yiyunet/dsh-learn-skills
```

**期望输出**：列出 `@yiyunet/dsh-learn-skills` 及其 `link:` 来源。

再看一眼 profile 清单里的 bundles 有没有它：

```powershell
Get-Content "$env:USERPROFILE\.dsh\profiles\web\package.json"
```

**期望**：`dependencies` 里有 `"@yiyunet/dsh-learn-skills": "link:D:/…/dsh-learn-skills"`，
且 `dsh.profile.bundles` 数组末尾有 `"@yiyunet/dsh-learn-skills"`。

### 2.4（可选）先干跑一次配置树

```powershell
dsh --profile web --dump-config | Select-String "learn-skills"
```

**期望**：能看到 `learn-skills` 这一行及其 `config`。这一步能在**不启动界面的情况下**
证明"配置层认了它"。

### 2.5 重启 Host

关掉当前 DSH（桌面壳 / `dsh web` 进程），重新启动。**必须重启** ——
`dsh.profile.bundles` 只在启动时读取。

### 2.6 装载成功的三个判据

| # | 判据 | 在哪看 |
|---|---|---|
| 1 | 输入区工具行出现 **`📖 AI学习 ▾`** | 会话输入框下方，紧挨「工作区内修改」右侧 |
| 2 | 斜杠菜单里出现 **`/learn`** | 输入框敲 `/` |
| 3 | `/learn help` 列出四个入口 | 直接敲这条命令 |

## §3 Phase 3：四个入口逐项验收

> 前置：**新建一个空工作区**（不要拿你日常在用的主工作区试第一次）。
> 例：`D:\temp\learn-test`，在里面新建会话并绑定它。
> 理由：初始预设会创建一整套目录，拿干净目录试，出问题一看就知道是谁写的。

### 3.1 未绑定工作区的引导

在一个**没绑工作区**的会话里点 `AI学习 ▾`。

### 3.2 入口一：初始预设（七轮问答）——**本次测试的重头戏**

点 `AI学习 ▾` → **初始预设**。

**在这一步要故意做几件"坏事"，看它扛不扛得住**：

| 试什么 | 期望行为 |
|---|---|
| 第 1 题输入**中文名**（例：小书童） | 接受 |
| 第 1 题输入 `a/b` | **回问一次**并说明"名字里不能出现 < > : " / \ | ? *" |
| 第 1 题输入一个**已存在的预设名**（例：标准模式） | 请你换名，**不覆盖、不替你改名** |
| 第 2 题**三段式**输入（例：`大学生 ｜ 面向大学英语 ｜ 更快掌握`） | 三段分别落进画像：职业 / 面向人群或事情 / 期望达到的效果；题面**回显第 1 题的名字** |
| 第 2 题只填一段（例：`大学生`） | 只当职业；另两段在预览里标"未知 —— 未填写"，**不替你拆段** |
| 第 2 题选**暂不透露** | 预览的画像摘要里写"未知 —— 未填写"，**不编造** |
| 第 3 题看选项 | **模型出题时**：题面与选项应明显贴着你的三参数（例："大学英语里你最想先拿下哪一块"）；**降级时**：7 个方向 + 1 个「其他，请输入」，可多选，措辞是"**可能**关注" |
| 第 3 题点「← 返回修改前面的回答」 | 回退一题重答；**改完职业/面向后，后续题（含第 3 题）的候选应重新生成**（不再是原来那一套） |
| 任意一题点「✕ 取消本次设置」 | 报"已完成 N / 7 题"，**没有任何文件被创建**；重新进入可续办 |

> **怎么判断模型到底有没有参与？** 两种观察：① 第 3~7 题的题头若出现"模型未参与"这类
> 通用题面、且选项是那套固定池 ⇒ 走了降级；② 看宿主日志里本插件的 `warn`
> （`第 N 题未由模型生成，已回退到通用候选：<原因>`）。降级**不中断流程**，但要知道它在降级。
> 最常见的两个原因：当前组合没挂 `agent-default-model`（拿不到 provider/model），
> 或模型调用超时（默认 20s）。

跑完七题后 **先别点确认**，看预览：

**期望预览包含**：画像摘要（名字 / 职业 / **面向什么** / **期望达到什么** / 关注方向 / 目标 /
基础 / 方式 / **最想先解决的一件事**；未填的标"未知 —— 未填写"）、预设定位、知识框架草案、

## §4 Phase 4：并发、回滚、冲突（真正见功夫的三条）

### 4.1 并发：重复点击不应产生两个写入任务

**期望**：第二次得到明确拒绝（"已有学习流程正在运行（distill · …）"），**不是排队，也不是静默**。

### 4.2 取消：取消之后不该有后续写入

启动 `初始预设`，答完两三题后点面板的 **取消**。

**期望**：报"已完成 N / 6 题…**没有任何文件被创建**"。

`AGENTS.md` 与 `knowledge/` **都不存在**。

### 4.3 回滚：不覆盖你写入之后的修改

用命令回滚上一批写入（批次号从 3.4 的结果里抄）：

```

```

**期望**：报告"还原 N 项 / 删除 N 项 / 跳过 N 项"。
核对：3.4 里新建的节点文件被**删除**了。

**关键的第二半**：把某个节点手工改一行，再回滚同一批。
**期望**：该文件**不动**，并出现在"跳过"里，理由写明"写入之后被改动过，不覆盖"。

### 4.4 冲突：别人改过的东西，插件不许覆盖

1. 手工编辑 `D:\temp\learn-test\AGENTS.md`，随便加一行；
2. 重新跑一遍 `初始预设` 并确认创建。

**期望**：结果里 `conflicts: 1`，且清单里的理由是"**拒绝覆盖**"。
**核对**：`AGENTS.md` 里你加的那行**还在**。

### 4.5 卸载后界面消失、数据保留

```powershell
dsh plugin --profile web remove @yiyunet/dsh-learn-skills
```

## §6 已知的"正常现象"（不是 bug）

1. **预设创建后当前会话没有变化** —— 这是宿主语义（standing mount 一进程一次，且只有空会话能切换预设）。
   界面会明确提示"新建会话"，插件**不会**宣称热更新。
2. **体检报告里"可读取的系统提示词"和"长期记忆"两项固定显示"无法访问"** ——
   宿主没有把这两样暴露给插件。**如实标注**优于编一个像样的推断。
3. **候选裁决里"验证状态"全是"未验证"** —— 用户点"保留"不等于事实已被验证。这是设计，不是漏做。
4. **`inbox/` 里出现 `.candidates-001.json` 这种点开头的文件** —— 那是候选批次数据，不是文档。
5. **六轮问答的问题出现在输入区（composer）里，不在菜单面板里** ——
   这是刻意的：用宿主自己的问答合成器，键盘/无障碍/取消交互全部跟随宿主。
6. **面板宽度在窄屏下会收窄**（`min(560px, 88vw)`），可能换行 —— 不遮挡原有控件的。
7. **`dsh.compatibility` 里写着 `unknown` 的版本不代表能跑** ——
   该字段**不被宿主强制**（官方字段是 `engines.dsh`，且自述"declarative until a reader enforces it"）。
   真正的门槛是运行时 `inject`：缺 `userQuestions` 或 `commands` 时插件**停在 inactive**。
8. **「确认创建」之后不会自动安装，也不会自己出现在新会话里** —— 2.1.0 起刻意的：
   安装 bundle 会在 Host 进程执行新代码，官方入口强制审批、服务方法无审批闸，
   插件代装＝替你越权。界面与返回值都会给出**可复制的命令**，装完才进名册。
9. **提示"读不到名册（agentPresets）⇒ 本次不创建"** —— 也不是 bug：预设身份＝声明行里的
   `config.id`，而注册表不扫目录；拿不到名册就无法保证不生成重复 id（官方：重复的
   preset ID 会导致声明加载失败）。这种情形下插件**一个文件都不写**，并明说原因。
