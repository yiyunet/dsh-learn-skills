# 测试

三组测试，都跑真实行为，不做"文案存在性检查"。

```sh
npm run static        # 免执行的静态一致性（import / 具名符号 / 语法 / 白名单）
npm test              # node --test test/*.test.mjs
npm run verify        # 发布契约断言（10 组）
npm run build         # 构建，含装载层自证（用最小 __ModuleLoader__ 桩真跑产物）
npm run inspect       # 产物体检（标记 / 装配 / 大小）
```

> `npm run static` **不需要 `npm install`**（零第三方依赖），因此即使还没装 esbuild
> 也能先跑它 —— 它是本目录在无 shell 环境下能给出的最高强度免执行检查。

## 二、发布契约断言（`npm run verify`）

10 组，每条对应一个**真实失败模式**（多数在生态基准件上踩过）：

| # | 断言 | 对应的失败模式 |
|---|---|---|
| ① | 必需文件齐全 | 发布包缺文件 |
| ② | 依赖节/lock 里不得出现 `@deepseek-ai/dsh-*` | 装第二份物理副本 → 破坏 Host 的 Symbol 查找 |
| ③ | 客户端产物含装载器 id / 槽位契约 / 菜单标题 / RPC 端点名 | 产物与真源漂移 → 界面不出现或调用 404 |
| ④ | 客户端产物不得含 ESM `import/export` | 源码未经打包就发出去 |
| ⑤ | RPC 端点名在宿主真源 / 客户端真源 / 产物三处一致 | 曾因端点名漂移导致面板渲染空壳而 RPC 不报错 |
| ⑥ | `inject` 只含 `userQuestions` / `commands` | 把可选服务写进 inject → 缺该能力的部署里**整体 inactive** |
| ⑦ | 无本机绝对路径与凭证形态；可选私有词表 | 公开发布前忘了脱敏 |
| ⑧ | `files` 白名单自洽 + **禁止安装期脚本** | `files` 漏件（`link:` 装载下完全看不见）；`postinstall` 会让 pnpm 10+ 消费者**安装直接失败** |
| ⑨ | `cordis.patch.yml` 含本包名且结构正确 | profile 不装载它 |
| ⑩ | 产物带"提交在 wrapper factory 内部"的证据 | 放外面 → 顶层执行 `require("react")` → 整个 `/plugins` 拼接 bundle 全灭（症状报在别的插件上） |

菜单顺序也在此断言：`MENU` 数组必须是 `init / distill / upgrade / audit`。

## 三、构建期自证（`npm run build`）

客户端产物不是"写出来就算"：构建用最小 `__ModuleLoader__` 桩把产物**真跑一遍**：

1. 脚本顶层必须能执行完（否则说明产物被放在了 factory 外面）；
2. 必须注册 `@yiyunet/dsh-learn-skills`；
3. factory 必须能物化出插件面并导出 `apply()`；
4. 产物必须含 9 个关键标记（含四个入口名，容忍 esbuild 的 `\uXXXX` 转义）。

宿主半侧也有自证：入口文件写出后必须存在，否则构建失败。
产物装配是"暂存区 → 原子替换"，失败时**旧 `lib/` 原样保留**。

### 2.2.0 首轮实测的 4 个失败（**根因与修复**）

| # | 失败用例 | 根因 | 性质 | 修复 |
|---|---|---|---|---|
| 1 | `第 4~7 题围绕清晰主题` —— 题头 `第 4 题 / 共 7 题 · goal` | 我改题头时把 `draftQuestions` 里原有的**中文标签覆盖成了英文 topic** | **真产品问题**（用户会看到半截洋文） | 题头一律走 `TOPIC_LABELS`；固定题直接沿用题库里那个含中文的题头 |
| 2 | `中途取消` —— 断言 `/已完成 1 \/ 6/` | 题序从 6 改 7，这条断言**漏改** | 测试基线漂移 | 改为 `new RegExp(\`已完成 1 / ${TOTAL_ROUNDS}\`)`，**不再写死数字** |
| 3 | `判据只在名册` —— `7 !== 6`（期待 6 次提问） | 同上 | 测试基线漂移 | 改用 `TOTAL_ROUNDS` |
| 4 | `buildMessages` —— `/已明确表示不填.*goal/` 不匹配 | 实际文案是 `用户**明确表示不填**的项：goal`，中间夹着 Markdown 的 `**` | **测试自己写错**（假阴性） | 正则改为 `/明确表示不填.*goal/` |

> **教训（值得记住的两条）**：
> ① **凡断言里写死轮次数字，改题序时必漏** —— 用导出的常量（`TOTAL_ROUNDS`）代替字面量。
> ② **改题面/题头的文案时，最容易丢的是"用户可见的中文标签"**：内部键（`goal`）与
> 展示名（`学习目标与典型任务`）必须分开，且展示名只能有一处定义。

## 五、尚未验证与已知限制

1. **公开发布未执行**：`dsh plugin --profile web add @yiyunet/dsh-learn-skills` 在
   `npm publish` 并 `npm view` 回读成功之前**不可用**。
2. **宿主兼容矩阵只实测一个版本**：`0.1.5-alpha.1` 标 `verified`，其余标 `unknown`。
3. **子目录级 `AGENTS.md` 的加载行为未核验**：体检报告因此标注"是否被加载取决于宿主实现"，
   插件不依赖它。
4. **问答的真实渲染未实测**：本插件复用宿主问答合成器，但"问题在输入区渲染出来
   长什么样、Tab 顺序如何"未在浏览器里看过（题序已由 2.1.0 的六题改为 2.2.0 的七题）。
5. **★ 模型出题路径未在真机跑过**（2.2.0 新增能力的**首要待验项**）：单测覆盖的是
   纯函数与"用假 llm 跑通一次流"，而**真机**还要验证三件单测覆盖不到的事：
   ① 当前组合确实挂着 `agent-default-model`（否则每轮都降级）；
   ② `ctx.get('llm')` 在**宿主 RPC 路径**上拿得到实例（单测里是注入的假对象，证不了这条）；
   ③ 真机延迟是否落在 20s 超时之内（超了不会报错，只会静默降级 —— 表现为"问题又变泛了"）。
   判据：看宿主日志里本插件的 `warn`（`第 N 题未由模型生成，已回退到通用候选：<原因>`）。
6. **会话消息读取按 API 探测**：`session.events()` 的形状若在宿主版本间变化，
   消息抽取会退化为"取不到"（如实标注），而不会抛错崩掉流程。
7. **体检的文件发现是一层深**：`<root>/<name>/AGENTS.md|SKILL.md|README.md` 与
   `<root>/*.md`；更深层的文档不会被扫到（与宿主 skill 发现同规则，属刻意选择）。
